     1→     1→# Mem0 AI Memory System - Comprehensive Technical Research Report
     2→     2→
     3→     3→## Executive Summary
     4→     4→
     5→     5→Mem0 ("mem-zero") is a production-ready, scalable memory layer for AI agents and applications. It provides persistent, self-improving memory capabilities that enable personalized AI interactions. The system is designed to dynamically extract, consolidate, and retrieve salient information from conversations.

    15→    15→## 1. Core Architecture
    16→    16→
    17→    17→### 1.1 High-Level Architecture
    18→    18→
    19→    19→Mem0 follows a **two-phase pipeline** architecture:
    20→    20→
    21→    21→```
    22→    22→┌─────────────────────────────────────────────────────────────────────────────┐
    23→    23→│                           MEM0 ARCHITECTURE                                  │
    24→    24→├─────────────────────────────────────────────────────────────────────────────┤
    25→    25→│                                                                              │
    26→    26→│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐                   │
    27→    27→│  │   Messages   │───>│  Extraction  │───>│   Storage    │                   │
    28→    28→│  │  (Input)     │    │   Pipeline   │    │   Layer      │                   │
    29→    29→│  └──────────────┘    └──────────────┘    └──────────────┘                   │
    30→    30→│         │                   │                    │                          │
    31→    31→│         │                   v                    v                          │
    32→    32→│         │           ┌──────────────┐    ┌──────────────┐                   │
    33→    33→│         │           │   Entity     │    │   Vector     │                   │
    34→    34→│         │           │   Linking    │    │   Store      │                   │
    35→    35→│         │           └──────────────┘    └──────────────┘                   │
    36→    36→│         │                   │                    │                          │
    37→    37→│         │                   v                    v                          │
    38→    38→│         │           ┌──────────────┐    ┌──────────────┐                   │
    39→    39→│         │           │   Memory     │    │   Hybrid     │                   │
    40→    40→│         └──────────>│   Retrieval  │<───│   Search     │                   │
    41→    41→│                     └──────────────┘    └──────────────┘                   │
    42→    42→│                                                                              │
    43→    43→└─────────────────────────────────────────────────────────────────────────────┘
    44→    44→```
    45→    45→
    46→    46→### 1.2 Core Components
    47→    47→
    48→    48→1. **Extraction Pipeline**: LLM-powered fact extraction from conversations
    49→    49→2. **Entity Linking**: Connects related memories across sessions
    50→    50→3. **Vector Storage**: Pluggable vector database layer
    51→    51→4. **Hybrid Search**: Semantic + BM25 + Entity boosting
    52→    52→5. **Memory Manager**: Orchestrates add/update/delete operations
    53→    53→
    54→    54→### 1.3 V3 Architecture (Current - April 2026)
    55→    55→
    56→    56→The new "Token-Efficient Memory Algorithm" introduces:
    57→    57→
    58→    58→| Feature | Description |
    59→    59→|---------|-------------|
    60→    60→| **Single-pass ADD-only extraction** | One LLM call, no UPDATE/DELETE operations |
    61→    61→| **Agent-generated facts** | First-class citizens with equal weight |
    62→    62→| **Entity linking** | Entities extracted, embedded, and linked across memories |
    63→    63→| **Multi-signal retrieval** | Semantic + BM25 keyword + entity matching in parallel |
    64→    64→| **Temporal Reasoning** | Time-aware retrieval for dated instances |

    68→    68→## 2. Memory Types
    69→    69→
    70→    70→Mem0 supports multiple memory types inspired by cognitive science:
    71→    71→
    72→    72→### 2.1 Memory Type Categories
    73→    73→
    74→    74→| Type | Description | Storage | Use Case |
    75→    75→|------|-------------|---------|----------|
    76→    76→| **Episodic Memory** | Summaries of past interactions or completed tasks | Vector Store | Conversation history, task completion |
    77→    77→| **Semantic Memory** | Relationships between concepts for reasoning | Vector Store + Graph | Facts, preferences, entity relationships |
    78→    78→| **Procedural Memory** | Execution history and agent actions | SQLite | Agent workflows, step-by-step processes |
    79→    79→| **Working Memory** | Current session context | In-memory | Active conversation context |
    80→    80→
    81→    81→### 2.2 Memory Structure
    82→    82→
    83→    83→```python
    84→    84→# Core Memory Item Structure
    85→    85→class MemoryItem:
    86→    86→    id: str                    # UUID identifier
    87→    87→    memory: str                # The actual memory text
    88→    88→    hash: str                  # Content hash for deduplication
    89→    89→    created_at: datetime       # Creation timestamp
    90→    90→    updated_at: datetime       # Last update timestamp
    91→    91→    
    92→    92→    # Entity Context

    96→    96→    
    97→    97→    # Additional Context

   101→   101→```

   105→   105→## 3. Extraction Algorithms
   106→   106→
   107→   107→### 3.1 ADD-only Extraction (V3)
   108→   108→
   109→   109→The V3 algorithm uses **single-pass, append-only extraction**:
   110→   110→
   111→   111→```
   112→   112→┌─────────────────────────────────────────────────────────────────────────────┐
   113→   113→│                     ADD-ONLY EXTRACTION FLOW                                 │
   114→   114→├─────────────────────────────────────────────────────────────────────────────┤
   115→   115→│                                                                              │
   116→   116→│  INPUT:                                                                      │
   117→   117→│  ┌─────────────────────────────────────────────────────────────────────┐    │
   118→   118→│  │ • New Messages (user/assistant conversation)                        │    │
   119→   119→│  │ • Summary (narrative of user profile from prior conversations)      │    │
   120→   120→│  │ • Recently Extracted Memories (up to 20, for deduplication)          │    │
   121→   121→│  │ • Existing Memories (relevant memories from vector store)            │    │
   122→   122→│  │ • Last k Messages (up to 20, for reference resolution)               │    │
   123→   123→│  │ • Observation Date (temporal anchor for relative references)         │    │
   124→   124→│  └─────────────────────────────────────────────────────────────────────┘    │
   125→   125→│                                                                              │
   126→   126→│  PROCESSING:                                                                 │
   127→   127→│  ┌─────────────────────────────────────────────────────────────────────┐    │
   128→   128→│  │ 1. Parse all messages (user AND assistant)                          │    │
   129→   129→│  │ 2. Extract facts, preferences, plans, relationships                  │    │
   130→   130→│  │ 3. Resolve temporal references (yesterday → specific date)          │    │
   131→   131→│  │ 4. Deduplicate against Recent/Existing Memories                      │    │
   132→   132→│  │ 5. Link to related existing memories                                 │    │
   133→   133→│  │ 6. Generate contextually rich, self-contained memories              │    │
   134→   134→│  └─────────────────────────────────────────────────────────────────────┘    │
   135→   135→│                                                                              │
   136→   136→│  OUTPUT:                                                                     │
   137→   137→│  ┌─────────────────────────────────────────────────────────────────────┐    │
   138→   138→│  │ {"memory": [                                                         │    │
   139→   139→│  │   {"id": "0", "text": "...", "attributed_to": "user",               │    │
   140→   140→│  │    "linked_memory_ids": ["uuid-of-related-memory"]},                │    │
   141→   141→│  │   {"id": "1", "text": "...", "attributed_to": "assistant"}          │    │
   142→   142→│  │ ]}                                                                   │    │
   143→   143→│  └─────────────────────────────────────────────────────────────────────┘    │
   144→   144→│                                                                              │
   145→   145→└─────────────────────────────────────────────────────────────────────────────┘
   146→   146→```
   147→   147→
   148→   148→### 3.2 Extraction Prompt Structure
   149→   149→
   150→   150→The `ADDITIVE_EXTRACTION_PROMPT` is the core extraction system prompt:
   151→   151→
   152→   152→**Key Extraction Guidelines:**
   153→   153→
   154→   154→1. **What to Extract from User Messages:**
   155→   155→   - Personal details, preferences, plans, relationships
   156→   156→   - Health/wellness, opinions, hobbies, emotional states
   157→   157→   - Entity attributes (breed, model, color, make, size)
   158→   158→   - Implicit preferences revealed through requests
   159→   159→   - Shared content and reference material
   160→   160→   - Firsts and milestones
   161→   161→   - Specific foods, meals, and who was present
   162→   162→
   163→   163→2. **What to Extract from Assistant Messages:**
   164→   164→   - Specific recommendations given
   165→   165→   - Plans or schedules created for the user
   166→   166→   - Information researched or provided
   167→   167→   - Agreements reached during conversation
   168→   168→
   169→   169→3. **Memory Quality Standards:**
   170→   170→   - **Contextually Rich**: "User has a dog named Poppy and their morning walks together are the highlight of their day"
   171→   171→   - **Self-Contained**: Replace pronouns with specific names
   172→   172→   - **Temporally Grounded**: Convert relative → absolute dates
   173→   173→   - **Numerically Precise**: Preserve exact quantities
   174→   174→   - **Proper Nouns Preserved**: Keep titles, names, brands exact
   175→   175→
   176→   176→### 3.3 Entity Extraction

   223→   223→## 4. Consolidation Process
   224→   224→
   225→   225→### 4.1 V2 Consolidation (Legacy - UPDATE/DELETE)
   226→   226→
   227→   227→The older V2 system used a four-operation model:
   228→   228→
   229→   229→| Operation | Description | When Used |
   230→   230→|-----------|-------------|-----------|
   231→   231→| **ADD** | Add new memory element | New information not in memory |
   232→   232→| **UPDATE** | Update existing element | Information changed/evolved |
   233→   233→| **DELETE** | Delete existing element | Contradictory information |
   234→   234→| **NONE** | No change | Already present or irrelevant |
   235→   235→
   236→   236→### 4.2 V3 ADD-Only Model (Current)
   237→   237→
   238→   238→The V3 algorithm **eliminates consolidation entirely**:
   239→   239→
   240→   240→```
   241→   241→┌─────────────────────────────────────────────────────────────────┐
   242→   242→│                    V3 ADD-ONLY MODEL                            │
   243→   243→├─────────────────────────────────────────────────────────────────┤
   244→   244→│                                                                 │
   245→   245→│  OLD (V2):                    NEW (V3):                         │
   246→   246→│  ┌─────────────────┐          ┌─────────────────┐               │
   247→   247→│  │ Extract Facts   │          │ Extract Facts   │               │
   248→   248→│  │       ↓         │          │       ↓         │               │
   249→   249→│  │ Compare to      │          │ Add to Store    │               │
   250→   250→│  │ Existing        │          │       ↓         │               │
   251→   251→│  │       ↓         │          │ Entity Linking  │               │
   252→   252→│  │ ADD/UPDATE/     │          │       ↓         │               │
   253→   253→│  │ DELETE/NONE     │          │ Done            │               │
   254→   254→│  │       ↓         │          │                 │               │
   255→   255→│  │ Re-consolidate  │          │                 │               │
   256→   256→│  └─────────────────┘          └─────────────────┘               │
   257→   257→│                                                                 │
   258→   258→│  Benefits:                                                      │
   259→   259→│  • ~50% faster (single LLM call)                               │
   260→   260→│  • Full history preserved                                       │
   261→   261→│  • Retrieval handles relevance ranking                          │
   262→   262→│  • No information loss from consolidation errors               │
   263→   263→│                                                                 │
   264→   264→└─────────────────────────────────────────────────────────────────┘
   265→   265→```
   266→   266→

   494→   494→## 7. Key Features
   495→   495→
   496→   496→### 7.1 Hybrid Search
   497→   497→
   498→   498→Mem0 combines multiple search signals:
   499→   499→
   500→   500→```
   501→   501→Combined Score = (Semantic + BM25 + Entity_Boost) / Max_Possible
   502→   502→
   503→   503→Where:
   504→   504→- Semantic: Vector similarity score
   505→   505→- BM25: Keyword matching score (normalized to [0,1])
   506→   506→- Entity_Boost: Entity linking boost (weight: 0.5)
   507→   507→- Max_Possible: 1.0 (semantic) + 1.0 (BM25) + 0.5 (entity)
   508→   508→```
   509→   509→
   510→   510→**BM25 Normalization:**
   511→   511→```python
   512→   512→def normalize_bm25(raw_score: float, midpoint: float, steepness: float) -> float:
   513→   513→    """Normalize BM25 score to [0, 1] using logistic sigmoid."""
   514→   514→    return 1.0 / (1.0 + math.exp(-steepness * (raw_score - midpoint)))
   515→   515→
   516→   516→# Query-length-adaptive parameters
   517→   517→if num_terms <= 3:
   518→   518→    midpoint, steepness = 5.0, 0.7
   519→   519→elif num_terms <= 6:
   520→   520→    midpoint, steepness = 7.0, 0.6
   521→   521→elif num_terms <= 9:
   522→   522→    midpoint, steepness = 9.0, 0.5
   523→   523→```
   524→   524→
   525→   525→### 7.2 Temporal Reasoning
   526→   526→
   527→   527→**Time Reference Resolution:**
   528→   528→- "yesterday" → day before Observation Date
   529→   529→- "last week" → week preceding Observation Date
   530→   530→- "next month" → month following Observation Date
   531→   531→- "recently" → shortly before Observation Date
   532→   532→
   533→   533→**Key Principle:** Always ground relative references to specific dates for meaningful long-term retrieval.
   534→   534→
   535→   535→### 7.3 Entity Resolution
   536→   536→
   537→   537→```python
   538→   538→# Entity linking workflow
   539→   539→def link_entities(new_memory, existing_memories):
   540→   540→    """
   541→   541→    1. Extract entities from new memory using spaCy
   542→   542→    2. Embed entities using same embedder
   543→   543→    3. Search for matching entities in existing memories
   544→   544→    4. Add matched memory IDs to linked_memory_ids
   545→   545→    """
   546→   546→    entities = extract_entities(new_memory.text)
   547→   547→    entity_embeddings = embed_entities(entities)
   548→   548→    matches = search_entities(entity_embeddings, existing_memories)
   549→   549→    new_memory.linked_memory_ids = [m.id for m in matches]
   550→   550→```
   551→   551→
   552→   552→### 7.4 Memory Importance & Deduplication
   553→   553→
   554→   554→**Deduplication Process:**
   555→   555→1. **Recent Memory Check**: Compare against last 20 extracted memories
   556→   556→2. **Existing Memory Check**: Vector search for semantically similar memories
   557→   557→3. **Skip if Equivalent**: If new fact matches existing (semantic equivalence), skip extraction
   558→   558→4. **Link if Related**: If same entity/topic but different event, extract and link
   559→   559→
   560→   560→### 7.5 Memory Expiration
   561→   561→
   562→   562→Mem0 does not implement automatic memory expiration. Instead:
   563→   563→- All memories are preserved (ADD-only model)
   564→   564→- Relevance is determined at retrieval time
   565→   565→- Temporal reasoning helps surface current/relevant memories

   628→   628→## 9. Code Examples
   629→   629→
   630→   630→### 9.1 Full Integration Example
   631→   631→
   632→   632→```python
   633→   633→from openai import OpenAI
   634→   634→from mem0 import Memory
   635→   635→
   636→   636→openai_client = OpenAI()
   637→   637→memory = Memory()
   638→   638→
   639→   639→def chat_with_memories(message: str, user_id: str = "default_user") -> str:
   640→   640→    # 1. Retrieve relevant memories
   641→   641→    relevant_memories = memory.search(
   642→   642→        query=message,
   643→   643→        filters={"user_id": user_id},
   644→   644→        top_k=3
   645→   645→    )
   646→   646→    memories_str = "\n".join(
   647→   647→        f"- {entry['memory']}" 
   648→   648→        for entry in relevant_memories["results"]
   649→   649→    )
   650→   650→
   651→   651→    # 2. Generate response with memory context
   652→   652→    system_prompt = f"""You are a helpful AI. Answer based on query and memories.
   653→   653→    
   654→   654→User Memories:
   655→   655→{memories_str}"""
   656→   656→    
   657→   657→    messages = [
   658→   658→        {"role": "system", "content": system_prompt},
   659→   659→        {"role": "user", "content": message}
   660→   660→    ]
   661→   661→    
   662→   662→    response = openai_client.chat.completions.create(
   663→   663→        model="gpt-4o-mini",
   664→   664→        messages=messages
   665→   665→    )
   666→   666→    assistant_response = response.choices[0].message.content
   667→   667→
   668→   668→    # 3. Create new memories from conversation
   669→   669→    messages.append({"role": "assistant", "content": assistant_response})
   670→   670→    memory.add(messages, user_id=user_id)
   671→   671→
   672→   672→    return assistant_response
   673→   673→```

   719→   719→## 10. Key Takeaways for Implementation
   720→   720→
   721→   721→### Phase 1: Extraction & Consolidation
   722→   722→
   723→   723→1. **Use ADD-only extraction** - Single LLM call, no UPDATE/DELETE
   724→   724→2. **Extract from both user and assistant messages**
   725→   725→3. **Implement contextually rich extraction** - Not atomic facts
   726→   726→4. **Ground temporal references** - Convert relative to absolute dates
   727→   727→5. **Preserve proper nouns exactly** - Critical for recall
   728→   728→
   729→   729→### Phase 2: Storage & Retrieval
   730→   730→
   731→   731→1. **Use hybrid search** - Semantic + BM25 + Entity boosting
   732→   732→2. **Implement entity extraction** - spaCy for NER
   733→   733→3. **Store entity embeddings separately** - For linking
   734→   734→4. **Track memory history** - SQLite for audit trail
   735→   735→
   736→   736→### Phase 3: Production Considerations
   737→   737→
   738→   738→1. **Choose vector DB based on scale** - Qdrant for open-source, Pinecone for managed
   739→   739→2. **Configure appropriate embedder** - text-embedding-3-small minimum
   740→   740→3. **Set up authentication** - JWT + API keys
   741→   741→4. **Implement rate limiting** - Protect extraction endpoints
