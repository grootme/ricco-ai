     1→# Mem0 AI Memory System - Comprehensive Technical Research Report

     3→## Executive Summary
     4→
     5→Mem0 ("mem-zero") is a production-ready, scalable memory layer for AI agents and applications. It provides persistent, self-improving memory capabilities that enable personalized AI interactions. The system is designed to dynamically extract, consolidate, and retrieve salient information from conversations.

    15→## 1. Core Architecture
    16→
    17→### 1.1 High-Level Architecture
    18→
    19→Mem0 follows a **two-phase pipeline** architecture:
    20→
    21→```
    22→┌─────────────────────────────────────────────────────────────────────────────┐
    23→│                           MEM0 ARCHITECTURE                                  │
    24→├─────────────────────────────────────────────────────────────────────────────┤
    25→│                                                                              │
    26→│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐                   │
    27→│  │   Messages   │───>│  Extraction  │───>│   Storage    │                   │
    28→│  │  (Input)     │    │   Pipeline   │    │   Layer      │                   │
    29→│  └──────────────┘    └──────────────┘    └──────────────┘                   │
    30→│         │                   │                    │                          │
    31→│         │                   v                    v                          │
    32→│         │           ┌──────────────┐    ┌──────────────┐                   │
    33→│         │           │   Entity     │    │   Vector     │                   │
    34→│         │           │   Linking    │    │   Store      │                   │
    35→│         │           └──────────────┘    └──────────────┘                   │
    36→│         │                   │                    │                          │
    37→│         │                   v                    v                          │
    38→│         │           ┌──────────────┐    ┌──────────────┐                   │
    39→│         │           │   Memory     │    │   Hybrid     │                   │
    40→│         └──────────>│   Retrieval  │<───│   Search     │                   │
    41→│                     └──────────────┘    └──────────────┘                   │
    42→│                                                                              │
    43→└─────────────────────────────────────────────────────────────────────────────┘
    44→```
    45→
    46→### 1.2 Core Components
    47→
    48→1. **Extraction Pipeline**: LLM-powered fact extraction from conversations
    49→2. **Entity Linking**: Connects related memories across sessions
    50→3. **Vector Storage**: Pluggable vector database layer
    51→4. **Hybrid Search**: Semantic + BM25 + Entity boosting
    52→5. **Memory Manager**: Orchestrates add/update/delete operations
    53→
    54→### 1.3 V3 Architecture (Current - April 2026)
    55→
    56→The new "Token-Efficient Memory Algorithm" introduces:
    57→
    58→| Feature | Description |
    59→|---------|-------------|
    60→| **Single-pass ADD-only extraction** | One LLM call, no UPDATE/DELETE operations |
    61→| **Agent-generated facts** | First-class citizens with equal weight |
    62→| **Entity linking** | Entities extracted, embedded, and linked across memories |
    63→| **Multi-signal retrieval** | Semantic + BM25 keyword + entity matching in parallel |
    64→| **Temporal Reasoning** | Time-aware retrieval for dated instances |

   105→## 3. Extraction Algorithms
   106→
   107→### 3.1 ADD-only Extraction (V3)
   108→
   109→The V3 algorithm uses **single-pass, append-only extraction**:
   110→
   111→```
   112→┌─────────────────────────────────────────────────────────────────────────────┐
   113→│                     ADD-ONLY EXTRACTION FLOW                                 │
   114→├─────────────────────────────────────────────────────────────────────────────┤
   115→│                                                                              │
   116→│  INPUT:                                                                      │
   117→│  ┌─────────────────────────────────────────────────────────────────────┐    │
   118→│  │ • New Messages (user/assistant conversation)                        │    │
   119→│  │ • Summary (narrative of user profile from prior conversations)      │    │
   120→│  │ • Recently Extracted Memories (up to 20, for deduplication)          │    │
   121→│  │ • Existing Memories (relevant memories from vector store)            │    │
   122→│  │ • Last k Messages (up to 20, for reference resolution)               │    │
   123→│  │ • Observation Date (temporal anchor for relative references)         │    │
   124→│  └─────────────────────────────────────────────────────────────────────┘    │
   125→│                                                                              │
   126→│  PROCESSING:                                                                 │
   127→│  ┌─────────────────────────────────────────────────────────────────────┐    │
   128→│  │ 1. Parse all messages (user AND assistant)                          │    │
   129→│  │ 2. Extract facts, preferences, plans, relationships                  │    │
   130→│  │ 3. Resolve temporal references (yesterday → specific date)          │    │
   131→│  │ 4. Deduplicate against Recent/Existing Memories                      │    │
   132→│  │ 5. Link to related existing memories                                 │    │
   133→│  │ 6. Generate contextually rich, self-contained memories              │    │
   134→│  └─────────────────────────────────────────────────────────────────────┘    │
   135→│                                                                              │
   136→│  OUTPUT:                                                                     │
   137→│  ┌─────────────────────────────────────────────────────────────────────┐    │
   138→│  │ {"memory": [                                                         │    │
   139→│  │   {"id": "0", "text": "...", "attributed_to": "user",               │    │
   140→│  │    "linked_memory_ids": ["uuid-of-related-memory"]},                │    │
   141→│  │   {"id": "1", "text": "...", "attributed_to": "assistant"}          │    │
   142→│  │ ]}                                                                   │    │
   143→│  └─────────────────────────────────────────────────────────────────────┘    │
   144→│                                                                              │
   145→└─────────────────────────────────────────────────────────────────────────────┘
   146→```
   147→
   148→### 3.2 Extraction Prompt Structure
   149→
   150→The `ADDITIVE_EXTRACTION_PROMPT` is the core extraction system prompt:
   151→
   152→**Key Extraction Guidelines:**
   153→
   154→1. **What to Extract from User Messages:**
   155→   - Personal details, preferences, plans, relationships
   156→   - Health/wellness, opinions, hobbies, emotional states
   157→   - Entity attributes (breed, model, color, make, size)
   158→   - Implicit preferences revealed through requests
   159→   - Shared content and reference material
   160→   - Firsts and milestones
   161→   - Specific foods, meals, and who was present
   162→
   163→2. **What to Extract from Assistant Messages:**
   164→   - Specific recommendations given
   165→   - Plans or schedules created for the user
   166→   - Information researched or provided
   167→   - Agreements reached during conversation
   168→
   169→3. **Memory Quality Standards:**
   170→   - **Contextually Rich**: "User has a dog named Poppy and their morning walks together are the highlight of their day"
   171→   - **Self-Contained**: Replace pronouns with specific names
   172→   - **Temporally Grounded**: Convert relative → absolute dates
   173→   - **Numerically Precise**: Preserve exact quantities
   174→   - **Proper Nouns Preserved**: Keep titles, names, brands exact

   223→## 4. Consolidation Process
   224→
   225→### 4.1 V2 Consolidation (Legacy - UPDATE/DELETE)
   226→
   227→The older V2 system used a four-operation model:
   228→
   229→| Operation | Description | When Used |
   230→|-----------|-------------|-----------|
   231→| **ADD** | Add new memory element | New information not in memory |
   232→| **UPDATE** | Update existing element | Information changed/evolved |
   233→| **DELETE** | Delete existing element | Contradictory information |
   234→| **NONE** | No change | Already present or irrelevant |
   235→
   236→### 4.2 V3 ADD-Only Model (Current)
   237→
   238→The V3 algorithm **eliminates consolidation entirely**:
   239→
   240→```
   241→┌─────────────────────────────────────────────────────────────────┐
   242→│                    V3 ADD-ONLY MODEL                            │
   243→├─────────────────────────────────────────────────────────────────┤
   244→│                                                                 │
   245→│  OLD (V2):                    NEW (V3):                         │
   246→│  ┌─────────────────┐          ┌─────────────────┐               │
   247→│  │ Extract Facts   │          │ Extract Facts   │               │
   248→│  │       ↓         │          │       ↓         │               │
   249→│  │ Compare to      │          │ Add to Store    │               │
   250→│  │ Existing        │          │       ↓         │               │
   251→│  │       ↓         │          │ Entity Linking  │               │
   252→│  │ ADD/UPDATE/     │          │       ↓         │               │
   253→│  │ DELETE/NONE     │          │ Done            │               │
   254→│  │       ↓         │          │                 │               │
   255→│  │ Re-consolidate  │          │                 │               │
   256→│  └─────────────────┘          └─────────────────┘               │
   257→│                                                                 │
   258→│  Benefits:                                                      │
   259→│  • ~50% faster (single LLM call)                               │
   260→│  • Full history preserved                                       │
   261→│  • Retrieval handles relevance ranking                          │
   262→│  • No information loss from consolidation errors               │
   263→│                                                                 │
   264→└─────────────────────────────────────────────────────────────────┘
   265→```

   494→## 7. Key Features
   495→
   496→### 7.1 Hybrid Search
   497→
   498→Mem0 combines multiple search signals:
   499→
   500→```
   501→Combined Score = (Semantic + BM25 + Entity_Boost) / Max_Possible
   502→
   503→Where:
   504→- Semantic: Vector similarity score
   505→- BM25: Keyword matching score (normalized to [0,1])
   506→- Entity_Boost: Entity linking boost (weight: 0.5)
   507→- Max_Possible: 1.0 (semantic) + 1.0 (BM25) + 0.5 (entity)
   508→```
   509→
   510→**BM25 Normalization:**
   511→```python
   512→def normalize_bm25(raw_score: float, midpoint: float, steepness: float) -> float:
   513→    """Normalize BM25 score to [0, 1] using logistic sigmoid."""
   514→    return 1.0 / (1.0 + math.exp(-steepness * (raw_score - midpoint)))
   515→
   516→# Query-length-adaptive parameters
   517→if num_terms <= 3:
   518→    midpoint, steepness = 5.0, 0.7
   519→elif num_terms <= 6:
   520→    midpoint, steepness = 7.0, 0.6
   521→elif num_terms <= 9:
   522→    midpoint, steepness = 9.0, 0.5
   523→```
   524→
   525→### 7.2 Temporal Reasoning
   526→
   527→**Time Reference Resolution:**
   528→- "yesterday" → day before Observation Date
   529→- "last week" → week preceding Observation Date
   530→- "next month" → month following Observation Date
   531→- "recently" → shortly before Observation Date
   532→
   533→**Key Principle:** Always ground relative references to specific dates for meaningful long-term retrieval.
   534→
   535→### 7.3 Entity Resolution
   536→
   537→```python
   538→# Entity linking workflow
   539→def link_entities(new_memory, existing_memories):
   540→    """
   541→    1. Extract entities from new memory using spaCy
   542→    2. Embed entities using same embedder
   543→    3. Search for matching entities in existing memories
   544→    4. Add matched memory IDs to linked_memory_ids
   545→    """
   546→    entities = extract_entities(new_memory.text)
   547→    entity_embeddings = embed_entities(entities)
   548→    matches = search_entities(entity_embeddings, existing_memories)
   549→    new_memory.linked_memory_ids = [m.id for m in matches]
   550→```
   551→
   552→### 7.4 Memory Importance & Deduplication
   553→
   554→**Deduplication Process:**
   555→1. **Recent Memory Check**: Compare against last 20 extracted memories
   556→2. **Existing Memory Check**: Vector search for semantically similar memories
   557→3. **Skip if Equivalent**: If new fact matches existing (semantic equivalence), skip extraction
   558→4. **Link if Related**: If same entity/topic but different event, extract and link
   559→
   560→### 7.5 Memory Expiration
   561→
   562→Mem0 does not implement automatic memory expiration. Instead:
   563→- All memories are preserved (ADD-only model)
   564→- Relevance is determined at retrieval time
   565→- Temporal reasoning helps surface current/relevant memories

   628→## 9. Code Examples
   629→
   630→### 9.1 Full Integration Example
   631→
   632→```python
   633→from openai import OpenAI
   634→from mem0 import Memory
   635→
   636→openai_client = OpenAI()
   637→memory = Memory()
   638→
   639→def chat_with_memories(message: str, user_id: str = "default_user") -> str:
   640→    # 1. Retrieve relevant memories
   641→    relevant_memories = memory.search(
   642→        query=message,
   643→        filters={"user_id": user_id},
   644→        top_k=3
   645→    )
   646→    memories_str = "\n".join(
   647→        f"- {entry['memory']}" 
   648→        for entry in relevant_memories["results"]
   649→    )
   650→
   651→    # 2. Generate response with memory context
   652→    system_prompt = f"""You are a helpful AI. Answer based on query and memories.
   653→    
   654→User Memories:
   655→{memories_str}"""
   656→    
   657→    messages = [
   658→        {"role": "system", "content": system_prompt},
   659→        {"role": "user", "content": message}
   660→    ]
   661→    
   662→    response = openai_client.chat.completions.create(
   663→        model="gpt-4o-mini",
   664→        messages=messages
   665→    )
   666→    assistant_response = response.choices[0].message.content
   667→
   668→    # 3. Create new memories from conversation
   669→    messages.append({"role": "assistant", "content": assistant_response})
   670→    memory.add(messages, user_id=user_id)
   671→
   672→    return assistant_response
   673→```

   719→## 10. Key Takeaways for Implementation
   720→
   721→### Phase 1: Extraction & Consolidation
   722→
   723→1. **Use ADD-only extraction** - Single LLM call, no UPDATE/DELETE
   724→2. **Extract from both user and assistant messages**
   725→3. **Implement contextually rich extraction** - Not atomic facts
   726→4. **Ground temporal references** - Convert relative to absolute dates
   727→5. **Preserve proper nouns exactly** - Critical for recall
   728→
   729→### Phase 2: Storage & Retrieval
   730→
   731→1. **Use hybrid search** - Semantic + BM25 + Entity boosting
   732→2. **Implement entity extraction** - spaCy for NER
   733→3. **Store entity embeddings separately** - For linking
   734→4. **Track memory history** - SQLite for audit trail
   735→
   736→### Phase 3: Production Considerations
   737→
   738→1. **Choose vector DB based on scale** - Qdrant for open-source, Pinecone for managed
   739→2. **Configure appropriate embedder** - text-embedding-3-small minimum
   740→3. **Set up authentication** - JWT + API keys
   741→4. **Implement rate limiting** - Protect extraction endpoints
