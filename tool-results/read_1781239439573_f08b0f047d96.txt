   485→- **User messages**: Personal facts, preferences, plans, experiences, things done / never done before, opinions, requests, implicit preferences revealed through questions
   486→- **Assistant messages**: Specific recommendations given, plans or schedules created, information researched, solutions provided, agreements reached
   487→
   488→Attribute correctly: use "User" for user-stated facts. For assistant-generated content, frame in terms of the user's context (e.g., "User was recommended X" or "User's plan includes X as discussed in conversation").
   489→
   490→Do NOT extract:
   491→- Vague assistant characterizations ("you seem passionate", "that sounds stressful") unless the user explicitly confirms them
   492→- Generic assistant acknowledgments ("Sure!", "Great question!")
   493→- Assistant meta-commentary about its own capabilities
   494→
   495→
   496→## Summary
   497→
   498→A narrative summary of the user's profile from prior conversations. May be empty for new users. Use it to enrich extractions — it holds established context like names, locations, and relationships.
   499→
   500→
   501→## Recently Extracted Memories
   502→
   503→Memories already captured from recent messages in this session (up to 20). This is your primary deduplication reference — do not re-extract information already captured here.
   504→
   505→
   506→## Existing Memories
   507→
   508→Memories currently in the system relevant to this conversation. Formatted as:
   509→[{"id": "uuid-string", "text": "..."}, ...]
   510→
   511→Use these ONLY for deduplication and linking — do NOT extract new memories from Existing Memories. Your extractions must come exclusively from New Messages. If new information in New Messages is semantically equivalent to an Existing Memory with no meaningful new context, skip it.
   512→
   513→When a new memory is related to an Existing Memory — same topic, overlapping entities, updated/shifted preference, follow-up event, or continuation of a narrative — include the Existing Memory's ID in the new memory's "linked_memory_ids" array. Your ADD output IDs remain sequential ("0", "1", ...) but linked_memory_ids uses the UUIDs from this list.
   514→
   515→
   516→IMPORTANT: An existing memory about an entity (e.g., "User has a dog named Max") does NOT mean all information about that entity has been captured. New events, activities, experiences, or details about a known entity MUST still be extracted as separate memories and linked back. Only skip extraction when the specific fact or event itself is already captured — not merely because the entity appears in an existing memory. "User has a dog named Max" and "User went on a camping trip with Max where they hiked and swam" are two distinct memories, not duplicates.
   517→
   518→
   519→## Last k Messages
   520→
   521→Recent messages (up to 20) preceding New Messages. Use to resolve references and pronouns in New Messages.
   522→
   523→
   524→## Observation Date
   525→
   526→When the conversation actually took place (e.g., "2023-05-24"). This is your ONLY temporal anchor for resolving time references.
   527→
   528→Resolve ALL relative references against Observation Date:
   529→- "yesterday" → day before Observation Date
   530→- "last week" → week preceding Observation Date
   531→- "next month" → month following Observation Date
   532→- "recently" → shortly before Observation Date
   533→- "just finished", "today" → on or near Observation Date
   534→
   535→CRITICAL: "User went to Paris last week" is useless 6 months later. "User went to Paris the week of May 15, 2023" is meaningful forever. Always ground relative references to specific dates.
   536→
   537→
   538→## Current Date
   539→
   540→Today's system date. May be years after Observation Date. Do NOT use this to resolve temporal references in messages — only Observation Date grounds user and assistant statements.
   541→

   543→## Optional Inputs
   544→
   545→- **includes**: Topics to focus on
   546→- **excludes**: Topics to skip
   547→- **custom_instructions**: User-defined rules (highest priority)
   548→- **feedback_str**: Adjust extraction based on this feedback

   551→# GUIDELINES
   552→
   553→## What to Extract
   554→
   555→Extract ALL memorable information from both user and assistant messages. Think broadly:
   556→
   557→**From user messages:**
   558→- Personal details, preferences, plans, relationships, professional context
   559→- Health/wellness, opinions, hobbies, emotional states
   560→- Entity attributes (breed, model, color, make, size)
   561→- Implicit preferences revealed through requests 
   562→- **Shared content and reference material** — when a user shares documents, case studies, articles, data, specifications, stat blocks, code, or any structured information, extract the key factual data FROM that content. The user shared it because they want it remembered.
   563→- Firsts and milestones — 'first call-out', 'just started', 'recently joined', etc.
   564→- Specific foods, meals, and who was present (e.g. 'dinner with mom — salads, sandwiches, homemade desserts').
   565→- Inspiration and motivation — what inspired someone to start something, who encouraged them.
   566→
   567→**From assistant messages (ONLY when genuinely new):**
   568→- Specific recommendations given (books, restaurants, products, services)
   569→- Plans or schedules created for the user
   570→- Information researched or provided (facts, instructions, solutions)
   571→- Agreements reached during conversation
   572→- **Personal facts, experiences, and details shared by named speakers** — in multi-speaker conversations, the "assistant" role may represent a real person sharing their own life (e.g., "Maria: I just got a new cat named Bailey"). Extract their personal information with the same rigor as user-stated facts, attributed to the speaker by name.
   573→
   574→Do NOT extract from assistant messages that merely restate, summarize, or confirm what the user already said. The user's own words are the primary source — if the user said it and the assistant echoed it, extract only once from the user's version. Note: a single assistant message may contain BOTH an echo AND new personal facts — skip the echo portion but still extract the new facts.
   575→
   576→Do NOT extract: greetings, filler, vague acknowledgments, or content too generic to be useful.
   577→
   578→**When in doubt, extract.** A slightly redundant memory is far less costly than a missing one. The deduplication system downstream will handle true duplicates — your job is to ensure nothing meaningful is lost.
   579→
   580→### Casual Topics Are Still Extractable
   581→
   582→Conversations about pets, hobbies, childhood memories, funny anecdotes, and personal preferences are NOT "chitchat" to be skipped. In a personal memory system, these casual revelations are often the MOST valuable — someone's pet's name, a childhood activity with a parent, a funny incident, a new hobby. Only skip messages that are PURELY phatic ("Hi!", "Sounds good!", "Thanks!") with zero informational content.
   583→
   584→### Extract Incidental Facts, Not Just Requests
   585→
   586→When a user asks a question or makes a request, their message often contains INCIDENTAL PERSONAL FACTS stated as context. These facts are just as extractable as the request itself:
   587→
   588→- "I've harvested cherry tomatoes from my garden — any companion plant suggestions?" → Extract BOTH "User grows cherry tomatoes in their garden" 
   589→- "I just started 'The Nightingale' by Kristin Hannah — can you recommend similar books?" → Extract BOTH "User started reading 'The Nightingale' by Kristin Hannah on [date]" 
   590→- "As an aspiring stand-up comedian, can you suggest Netflix comedy specials?" → Extract BOTH the career aspiration 
   591→- "My daughter Sara loves painting — where can I find kids' art classes?" → Extract "User has a daughter named Sara who loves painting" 
   592→
   593→Do NOT let the request overshadow the facts. A question about companion plants is transient; the fact that the user grows cherry tomatoes is a persistent personal detail worth remembering.
   594→
   595→**IMPORTANT — Extract ALL dimensions of a conversation.** A single session may contain career facts, entertainment preferences, scheduled plans, and personal opinions. Extract each dimension as a separate memory. Do not let one dominant topic cause you to miss secondary information.
   596→
   597→### Shared Photos and Images
   598→
   599→When a message contains a photo description (e.g., "[Shared photo: ...]" or describes sharing/showing an image), extract factual information from BOTH the surrounding conversation text AND the photo description. The photo description provides visual context that may contain important details:
   600→
   601→- A photo of a group at a park → extract the activity (e.g., "had a picnic at the park")
   602→- A photo showing a specific object, place, or person → extract what is depicted
   603→- A photo with visible text (signs, posters, book covers) → extract the text content
   604→
   605→## Memory Quality Standards
   606→
   607→### Contextually Rich, Not Atomic
   608→Capture the full picture — fact AND surrounding context — in a single unified memory, not scattered fragments.
   609→
   610→Bad: "User has a dog" | Good: "User has a dog named Poppy and their morning walks together are the highlight of their day"
   611→
   612→This applies especially to **transitions and changes**. When the user describes changing, switching, replacing, stopping, or trying something new in place of something else, the memory MUST capture the transition — what the new state is AND what it replaces or changes from. The relationship between old and new is critical context. Without it, the system has an isolated new fact with no understanding of what changed.
   613→
   614→Bad: "User prefers oat milk lattes"
   615→Good: "User switched from almond milk to oat milk lattes after developing an almond sensitivity"
   616→
   617→Bad: "User is taking online Spanish classes on Wednesdays"
   618→Good: "User switched from in-person French classes to online Spanish classes on Wednesdays after relocating"
   619→
   620→When the change is explicitly temporary or a trial, capture that too — "for a month", "trying out", "testing" — these signal the old arrangement may resume.
   621→
   622→### Clean Factual Statements
   623→Preserve the FULL meaning including emotional reactions, motivations, and subjective experiences. Remove filler words and conversation mechanics (greetings, "like", "you know"), but KEEP:
   624→- Emotional states: "scared but reassured", "happy and thankful", "liberated and empowered"
   625→- Motivations and reasons: "motivated by her own journey and the support she received"
   626→- Subjective descriptions: "resilient", "therapeutic", "nerve-wracking"
   627→
   628→### Self-Contained
   629→Every memory must be understandable on its own. Replace all pronouns with specific names or "User."
   630→
   631→### Concise but Complete (15-80 words, up to 100 for detail-rich content)
   632→1-2 sentences per memory (up to 3 for content with multiple proper nouns, specific quantities, or enumerated items). When a topic has too many details, split into multiple focused memories rather than compressing details away. NEVER sacrifice a proper noun, title, date, or specific detail to meet a word count — completeness beats brevity.
   633→
   634→### Temporally Grounded
   635→Preserve exact dates, durations, and temporal relationships. Convert relative → absolute using Observation Date (NOT Current Date). NEVER convert absolute → vague. "18 days" stays "18 days", not "some time."
   636→
   637→### Numerically Precise
   638→Preserve exact quantities as stated. "416 pages" stays "416 pages", not "about 400 pages."
   639→
   640→### Preserve Specific Details — Never Generalize Concrete Information
   641→
   642→When information contains specific details — whether quantities, identifiers, descriptions, visual details, quoted text, named objects, proper nouns, or any concrete information — those specifics MUST survive extraction. Replacing a specific detail with a vague category is a critical error.
   643→
   644→#### Proper Nouns and Titles Should be Preserved
   645→
   646→Book titles, movie titles, game names, song titles, restaurant names, neighborhood names, brand names, character names, and named places are the HIGHEST-VALUE details in a memory. Users search by name — a memory without the name is unfindable. ALWAYS preserve exact proper nouns:
   647→
   648→- "watched 'Eternal Sunshine of the Spotless Mind'" → KEEP the full title
   649→- "went to Woodhaven for a road trip" → KEEP "Woodhaven"
   650→- "tried the new restaurant Osteria Francescana" → KEEP "Osteria Francescana", NOT "a new restaurant"
   651→- "reading 'A Court of Thorns and Roses'" → KEEP the title in quotes, NOT "a fantasy book"
   652→- "his favorite character is Aragorn from Lord of the Rings" → KEEP "Aragorn" and "Lord of the Rings"
   653→
   654→#### Qualifiers and Specific Attributes Are Essential
   655→
   656→Never generalize specific qualifiers. The qualifier is almost always the detail that matters most for recall:
   657→
   658→- "promoted to assistant manager" → KEEP "assistant manager", NOT "manager"
   659→- "ordered grilled salmon and roasted vegetables" → KEEP "grilled salmon and roasted vegetables", NOT "healthy meal"
   660→- "started doing aerial yoga" → KEEP "aerial yoga", NOT "yoga" or "a workout class"
   661→- "painted a forest scene in watercolors" → KEEP "a forest scene in watercolors", NOT "started painting"
   662→- "drove a Ferrari 488 GTB" → KEEP "Ferrari 488 GTB", NOT "sports car"
   663→- "scored 3 goals in the semifinal" → KEEP "3 goals in the semifinal", NOT "scored several goals"
   664→- "walks her dogs multiple times a day" → KEEP "multiple times a day", NOT "regularly" or "daily"
   665→
   666→If the input is specific, the memory must be equally specific. The concrete details are precisely what distinguishes a useful memory from a useless one. NEVER replace a specific noun, number, title, or description with a vague category or paraphrase — this destroys the information the user actually shared.
   667→
   668→### Meaning-Preserving
   669→Capture the EXACT meaning of what was said. Read carefully:
   670→- "Didn't get to bed until 2 AM" = went TO BED at 2 AM (late bedtime), NOT "slept until 2 AM" (late wakeup)
   671→- "Can't stop eating chocolate" = eats a lot of chocolate, NOT has stopped eating chocolate
   672→- "I used to love hiking" = no longer loves hiking, NOT currently loves hiking
   673→
   674→Misinterpreting the user's words is worse than not extracting at all.
   675→
   676→
   677→## Integrity Rules
   678→
   679→- **No Fabrication**: Every detail must trace to the inputs. If you can't point to where it came from, don't include it.
   680→- **No Implicit Attribute Inference**: Don't infer gender, age, ethnicity, etc. from names or context. Only record explicitly stated attributes.
   681→- **Correct Attribution**: Distinguish user-stated facts from assistant-provided information. Frame assistant content appropriately.
   682→- **No Echo Extraction**: When an assistant message restates, summarizes, or confirms information the user already provided in the same conversation, do NOT extract it again from the assistant's message. Only extract from assistant messages when they contribute genuinely NEW information not already present in the user's messages — specific recommendations, newly created plans or schedules, researched facts, or solutions the assistant provided that the user did not state themselves. If the user says "I want daily check-ins at 7:30 AM" and the assistant responds "I've set up daily check-ins at 7:30 AM", that is already captured from the user's message — do not extract a second memory from the assistant's echo.
   683→- **No Within-Response Duplication**: Each piece of information must appear exactly ONCE in your output, regardless of how many messages mention it. Before finalizing your output, review your extractions and remove any that are semantically equivalent to another extraction in the same response. Two memories about the same fact phrased differently are redundant — keep the richer one and drop the other.
   684→- **No Meta-Extraction**: Extract the CONTENT of what was shared, not a description of the user's action. When a user shares a document, data, or reference material, extract the actual facts FROM that material.
   685→  - WRONG: "User asked for the introductory paragraph to be shortened" / "User shared a case summary for optimization"
   686→  - RIGHT: "The Bajimaya v Reward Homes case involved construction starting in 2014, contract signed in 2015, with completion due by October 2015" / "The tribunal found Reward Homes breached its contract through poor workmanship, waterproofing defects, and non-compliance with the Building Code of Australia"
   687→  - WRONG: "Assistant created a D&D adventure with enemies"
   688→  - RIGHT: "The Lost Temple of the Djinn adventure includes 4 Mummies (AC 11, 45 HP), 2 Construct Guardians (AC 17, 110 HP), and 6 Skeletal Warriors (AC 12, 22 HP)"
   689→- **No Detail Contamination from Context**: When extracting from New Messages, do NOT import or merge details from Existing Memories or Recent Memories into the new extraction UNLESS the new message explicitly references those details. If the New Message says "I had a great meal" and an Existing Memory says "User's favorite restaurant is Olive Garden," do NOT produce "User had a great meal at Olive Garden" — the new message never mentioned the restaurant. Each extraction must be faithful to its source message only.
   690→
   691→
   692→## Memory Linking
   693→
   694→When extracting a new memory, check if it relates to any Existing Memory. Add related Existing Memory IDs to "linked_memory_ids". Link when:
   695→
   696→- **Same entity/topic**: New fact about a person, place, or thing already mentioned
   697→- **Updated preference**: A changed or evolved opinion on something previously captured
   698→- **Continuation**: Follow-up event or next step in a previously captured narrative
   699→- **Contradiction**: New information that conflicts with an existing memory
   700→
   701→Do NOT link memories that merely share a vague theme. Links should be specific and meaningful — the linked memories should be about the same specific entity, event, or topic. If no existing memories are related, omit linked_memory_ids or pass an empty array.

   965→PAST_MESSAGE_TRUNCATION_LIMIT = 300

   968→def _truncate_content(text, limit=PAST_MESSAGE_TRUNCATION_LIMIT):
   969→    """Truncate text to limit characters, appending '...' when shortened."""
   970→    if len(text) <= limit:
   971→        return text
   972→    return text[:limit] + "..."
   973→
   974→
   975→def _format_summary(summary):
   976→    """Extract summary text from a string or dict with a 'summary' key."""
   977→    if isinstance(summary, dict):
   978→        return summary.get("summary", "")
   979→    return summary or ""
   980→
   981→
   982→def _format_conversation_history(messages):
   983→    """Format message dicts into 'role: content' lines with truncation."""
   984→    if not messages:
   985→        return ""
   986→    result = ""
   987→    for msg in messages:
   988→        role = msg.get("role", "")
   989→        content = msg.get("message") or msg.get("content", "")
   990→        if role and content:
   991→            result += f"{role}: {_truncate_content(content)}\n"
   992→    return result
   993→
   994→
   995→def _serialize_memories(memories):
   996→    """JSON-serialize a list of memory objects, defaulting to '[]'."""
   997→    return json.dumps(memories or [], ensure_ascii=False)
   998→
   999→
  1000→def _format_new_messages(new_messages):
  1001→    """Pass through if already a string, otherwise JSON-serialize."""
  1002→    if isinstance(new_messages, str):
  1003→        return new_messages
  1004→    return json.dumps(new_messages or [], ensure_ascii=False)

  1007→def _resolve_dates(current_date=None, observation_date=None):
  1008→    """Resolve current and observation dates, defaulting to today."""
  1009→    if current_date is None:
  1010→        current_date = datetime.now(timezone.utc).date().isoformat()
  1011→    if observation_date is None:
  1012→        observation_date = current_date
  1013→    return current_date, observation_date

  1016→def generate_additive_extraction_prompt(
  1017→    summary=None,
  1018→    recently_extracted_memories=None,
  1019→    existing_memories=None,
  1020→    new_messages=None,
  1021→    *,
  1022→    last_k_messages=None,

  1024→    timestamp=None,
  1025→    custom_instructions=None,

  1029→
